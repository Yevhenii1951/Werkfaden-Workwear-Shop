## Restock policy (defined here, per ../contract.md)

Stock lives in the inventory module as a per inventory-item + location level; the operator edits it with `POST /admin/inventory-items/:id/location-levels/:location_id` `{ stocked_quantity }`.

- **Fulfillment** (`POST /admin/orders/:id/fulfillments`): releases the order's reservation and subtracts the fulfilled quantity from `stocked_quantity`.
- **Cancellation** of an unfulfilled order (`POST /admin/orders/:id/cancel`): releases the reservation; `stocked_quantity` is unchanged, so reserved units return to available.
- **Refund** (`POST /admin/payments/:id/refund`): changes payment state only and never touches stock. A refund does not imply restocking; returning units to stock is an explicit operator stock edit (or a future return disposition), not a side effect of the refund.

Storefront reflects the edit: adding a variant to a cart validates availability, so a sold-out variant is refused (HTTP 400) and a restocked one is accepted.
