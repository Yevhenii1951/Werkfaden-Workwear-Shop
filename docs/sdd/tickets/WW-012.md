# WW-012: Discount codes at checkout

Status: open.

## Intent / delivers

Buyer can apply and remove a discount code in cart/checkout and the discount
is calculated server-side by Medusa. The storefront component
(`modules/checkout/components/discount-code`) and `applyPromotions` server
action already exist from the starter; the Promotion module is on by default.
What is missing: a real demo promotion to apply, German-error verification,
and reject/boundary coverage (invalid, expired, usage-limited, wrong-region
codes).

## Blocked by

Nothing (WW-011 independent; can run in parallel or second).

## Complexity

Implementation: low-medium. Review: medium — touches money calculation;
fresh read-only review required per tier rules for payment-adjacent work.

## Context to read

This ticket + ../contract.md + ../state.md.

## Verification scenario

GIVEN a cart with eligible items and a valid active code WHEN the code is
applied in checkout THEN totals drop server-side and the promotion is visible
in the cart; WHEN an unknown/expired/non-applicable code is applied THEN the
cart totals stay unchanged and a German error is shown — never a client-side
only discount.

## Acceptance criteria

- A repeatable setup (`setup-promotions.ts`, idempotent, wired into root
  scripts or documented) creates demo promotions in the dev DB: at least one
  percentage code and one fixed-amount code for the DE/EUR region, with an
  expiry or usage-limit variant available for negative tests. Codes are demo
  facts, documented in README/handover, never presented as real offers.
- Integration coverage on the test DB: valid code applies and changes totals;
  unknown code rejected; expired/usage-limited code rejected; removing a code
  restores totals. Discount math is asserted on server-derived totals only.
- Storefront shows the applied code with remove affordance in German; error
  copy is human German, not a raw API message.
- `npm run check` green; no weakening of existing cart/checkout tests.

## Non-goals

No promotion builder UI, no automatic campaigns, no shipping-discount rules
beyond what core supports out of the box, no changes to the free-shipping
threshold logic (FR-5).

## Checks / browser evidence

Browser scenario: cart → code apply → total change → remove → restore, at
390 px and 1440 px. Record in PR description.
