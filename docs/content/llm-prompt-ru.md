# Промпт для подготовки контента Werkfaden

Скопируй текст ниже в другую LLM. Результат передай файлами Markdown/JSON/CSV. Это контент-пакет, а не реализация сайта и не импортный файл Medusa.

---

Ты — немецкоязычный ecommerce-редактор и специалист по подготовке товарных данных. Подготовь подробный, внутренне согласованный контент-пакет для портфолио интернет-магазина рабочей одежды Werkfaden. Рабочее имя не проверено на товарные знаки: не заявляй юридическую уникальность или регистрацию бренда.

## Контекст и границы

- Проект: Medusa + Next.js, Германия, интерфейс и все готовые тексты на немецком (de-DE). Пояснения автору — по-русски.
- Purpose: PORTFOLIO. Магазин демонстрирует реальные сценарии, но не ведёт торговлю. Оплата только sandbox. Не выдавай компанию за существующую.
- Покупатели: небольшие Handwerksbetriebe, клининг, монтажные и садовые фирмы, а также частные покупатели. Первая версия допускает B2C: не придумывай ограничения «только для предпринимателей».
- Основной ассортимент: повседневная рабочая и командная одежда. Это не сертифицированная защитная одежда / PSA. Не включай каски, респираторы, защитную обувь или сигнальную защитную одежду.
- Дополнительный сценарий: запрос логотипа/нанесения на партию. Стоимость и сроки согласуются вручную. Отправка запроса не создаёт оплаченный заказ, не резервирует остатки и не означает согласование макета.
- География MVP: доставка только по Германии, валюта EUR, один склад.
- Цель текстов: помочь выбрать изделие, размер и следующий шаг. Без рекламной воды, fake urgency и длинных SEO-повторов.
- Дизайн лендинга позже. Не генерируй код, layout, библиотеки, анимации и frontend-промпты.

## Факты, которые запрещено выдумывать

Не создавай существующие адреса, USt-IdNr., HRB, владельцев, телефон, отзывы, сертификаты, партнёров, стаж, продажи, гарантии, рейтинги, «Made in Germany», экологические и медицинские заявления. Не используй реальные бренды и скопированные описания. Не обещай «wasserdicht», «schnittfest», «flammsicher», соответствие EN/ISO, если данных нет.

Все характеристики, цены, остатки, таблицы размеров и условия магазина — явно обозначенные демонстрационные данные. Краткое предупреждение должно стоять в README пакета, а не повторяться внутри каждого товарного абзаца. Предложи отдельный заметный баннер магазина: «Demo-Shop — keine echten Bestellungen oder Zahlungen».

Юридические страницы — только структура и список фактов для проверки. Не выдавай LLM-текст за готовый юридический документ. Никаких фальшивых контактов для Impressum; используй [BETREIBER], [ANSCHRIFT], [KONTAKT] и другие явные placeholders.

## 1. Позиционирование и голос бренда — brand.md

- Одно позиционирование, 3 ценностных предложения без неподтверждённых фактов.
- Аудитории и задачи покупателей, коротко.
- Тон: простой, профессиональный, спокойный немецкий. Везде обращение Sie; единая терминология: Artikel, Variante, Größe, Farbe, Warenkorb, Bestellung, Veredelungsanfrage.
- Слоган: 3 варианта, по 4–8 слов. Один рекомендуемый.
- 20 терминов и правила написания размеров, цвета, цен, кнопок.
- Описание бренда 70–100 слов, не выдумывающее историю компании.

## 2. Категории — categories.json

Ровно 5 категорий: T-Shirts, Poloshirts, Sweatshirts & Hoodies, Jacken & Westen, Arbeitshosen.

Для каждой: id (стабильный machine-readable), slug, name_de, intro_de (40–70 слов), seo_title_de (до 60 знаков), seo_description_de (до 160 знаков), filter_suggestions, image_key.

Слаги — ASCII lowercase с дефисами. Фильтры MVP: категория, размер, цвет, цена, наличие. Не добавляй фильтры по сертификатам.

## 3. Каталог — products.json

Ровно 25 продуктов: по 5 на категорию. Не генерируй 1000 товаров: качество и согласованность важнее объёма. Названия простые и различимые, без реальных товарных марок.

Формат каждого продукта:

```json
{
  "content_id": "WF-TS-001",
  "slug": "team-t-shirt-basic",
  "name_de": "Team T-Shirt Basic",
  "category_id": "t-shirts",
  "subtitle_de": "Короткий немецкий подзаголовок",
  "description_de": "Немецкий текст 80–130 слов",
  "benefits_de": ["3–5 конкретных особенностей"],
  "material_de": "Демонстрационный состав с суммой 100%",
  "fabric_weight_gsm": 180,
  "fit_de": "Regular Fit",
  "care_de": ["Согласованные инструкции без непроверенных утверждений"],
  "size_guide_id": "tops-regular",
  "customization_eligible": true,
  "customization_note_de": "На этой модели можно запросить нанесение; проверка после получения файла",
  "seo_title_de": "До 60 знаков",
  "seo_description_de": "До 160 знаков",
  "image_keys": ["wf-ts-001-front", "wf-ts-001-back", "wf-ts-001-detail"],
  "variants": [
    {
      "sku": "WF-TS-001-NV-M",
      "size": "M",
      "color_id": "navy",
      "color_name_de": "Marineblau",
      "color_hex": "#172B46",
      "price_gross_eur_cents": 2490,
      "stock_quantity": 12,
      "weight_g": 220,
      "image_keys": ["wf-ts-001-navy-front"]
    }
  ]
}
```

Правила данных:

- Каждый SKU уникален, ASCII, стабилен. content_id — ключ контента, не ID Medusa.
- Деньги — целые евроценты, не float и не строки. Выводимые цены с немецкой запятой: 24,90 €.
- Для демонстрации используем цены brutto с моделью НДС 19%; настройку налогового расчёта выполняет разработчик. Никакого двойного добавления НДС.
- Ориентиры демонстрационных цен: T-Shirts 15–35 €, Poloshirts 25–55 €, Sweatshirts/Hoodies 35–85 €, Jacken/Westen 45–130 €, Arbeitshosen 40–100 €.
- На продукт — 2 цвета × 3 размера = 6 вариантов; суммарно 150 вариантов. Для верха S/M/L либо M/L/XL, для брюк 48/50/52. Покажи явные полные комбинации.
- Каноническая палитра из 5 цветов: Schwarz, Marineblau, Anthrazit, Weiß, Oliv. IDs и hex должны быть одинаковыми во всём пакете.
- Есть минимум 5 sold-out вариантов, минимум 5 вариантов с остатком 1, остальные с остатком 2–30. Остаток — не доказательство работающего резервирования.
- Минимум 5 продуктов недоступны для нанесения; не обещай конкретную технологию печати для каждой ткани без проверки.
- Без скидок, compare-at prices, сертификатов и EAN в MVP. SKU не является EAN. Если впоследствии нужны штрихкоды, не выдумывай зарегистрированные GTIN.
- Согласуй массу изделия и толщину ткани. fabric_weight_gsm может быть null, если характеристика неуместна.

## 4. Проверяемая таблица вариантов — variants.csv

UTF-8, RFC 4180, запятая как разделитель, одна строка на вариант. Колонки:
product_content_id,product_slug,sku,size,color_id,color_name_de,color_hex,price_gross_eur_cents,stock_quantity,weight_g,customization_eligible

Ровно 150 строк данных. Значения обязаны совпадать с products.json. Этот CSV — промежуточный контент-формат; не называй его готовым импортом Medusa.

## 5. Размеры и материалы — size-guides.json + buying-guide.md

- 3 таблицы: tops-regular, outerwear-regular, trousers-regular.
- Измерения в сантиметрах, явно укажи: размеры тела или изделия. Не смешивай в одной таблице.
- Каждая используемая размерная метка должна существовать в связанной таблице. Границы диапазонов возрастают, «плечи/талия/длина» подписаны понятно.
- Это демо-таблицы, не измерения существующего производителя. Для реального каталога их заменяют.
- Инструкция измерения: 5–7 шагов; совет при промежуточном размере без гарантий посадки.
- Короткий материал о выборе рабочей одежды и уходе; без safety-обещаний.

## 6. Тексты страниц — pages.md

Подготовь готовые немецкие блоки с устойчивыми ключами:

- Homepage: H1, вводный абзац, 2 CTA, 5 карточек категорий, 3 преимущества, блок запроса логотипа. Только контент, без дизайна.
- Über uns: честное описание концепции demo, без фиктивной биографии.
- Für Unternehmen: как собрать одежду для команды, 3–4 шага заказа.
- Veredelung anfragen: процесс, что отправить, что будет после заявки.
- Kontakt: вводный текст; реальные контактные сведения оставь placeholders.
- Größenberatung, Versand & Lieferung, Rückgabe & Erstattung, FAQ.
- Не создавай блог, отзывы, истории клиентов и fake logos.

## 7. Единые демонстрационные условия — demo-policies.json

Отметь все следующие значения как demo-only:

- Германия, EUR, цены brutto; никакой доставки за пределы Германии.
- Стоимость стандартной доставки: 5,90 € brutto. Бесплатная доставка от 100,00 € стоимости товаров после скидок, без доставки; в MVP скидки не реализованы.
- Для обычных товаров: примерный срок 3–5 Werktage; прямо указать в пакете, что это демонстрационный сценарий, а не обязательство продавца.
- Для нанесения: цена и срок после ручной проверки; без фиксированного минимума партии, обещанного срока ответа и гарантии результата.
- Оплата: только Stripe-Testmodus; не обещать PayPal, Klarna, Rechnungskauf или наличные.
- Возвраты: описать demo-процесс запроса и обработки; не придумывать адрес возврата, правила оплаты пересылки или исключения из Widerruf. Юридические решения перенести в checklist.
- Для реального запуска эти условия должны быть подтверждены владельцем бизнеса и отражены в настройках магазина.

## 8. FAQ — faq.json

18 вопросов: 5 размеры/уход, 4 заказ/доставка, 3 оплата/demo, 3 нанесение, 3 возврат/контакт. Формат id, topic, question_de, answer_de. Ответы 30–70 слов, строго согласованы с demo-policies.json.

## 9. UI-тексты — ui.de.json

Вложенные группы: navigation, catalog, product, cart, checkout, account, orders, customization, forms, errors, demo.

Включи кнопки, пустые состояния, loading, sold out, выбор варианта, ошибки формы, недоступный товар, изменение цены/остатка, отказ/отмену оплаты, неопределённый результат оплаты, запрет доступа, сообщение о повторной заявке. Не утверждай успех, когда сервер ещё не подтвердил операцию.

Используй именованные placeholders: {count}, {price}, {orderNumber}. Не HTML и не исполняемый код. Для формы нанесения: компания необязательна, имя, email, выбранный товар/вариант, количество, комментарий, файл, подтверждение права использования загружаемого логотипа. Не смешивай это с согласием на маркетинг.

## 10. Письма — emails.md

8 шаблонов, каждый с subject_de, preview_de, body_de и placeholders:
подтверждение заказа; неуспешная оплата/повторная попытка; отправка; отмена; возврат денег; получение Veredelungsanfrage; уведомление администратору о заявке; ручное предложение по заявке.

Не вставляй персональные данные, credentials и банковские реквизиты. Письмо о заказе и письмо об оплате не должны противоречить статусам. Письмо о заявке не является подтверждением заказа. Шаблоны не означают, что доставка всех писем уже реализована в MVP.

## 11. Изображения — image-manifest.json + image-prompts.md

- 3 базовых изображения каждого продукта (front/back/detail), дополнительные цветовые изображения по необходимости; 5 категорий; 3 lifestyle-сцены.
- В manifest: image_key, suggested_filename, product_content_id или null, role, aspect_ratio, alt_de, prompt_en, status (needed), source_license (not_provided).
- Промпты для генерации на английском: одно и то же изделие, согласованные цвет, швы и крой; нейтральный светлый фон для каталога; без чужих брендов, текста, водяных знаков и защитных сертификатов.
- Hero/lifestyle: взрослые люди, реалистичная одежда и обстановка; избегай опасных работ и изображения обычной одежды как защитного снаряжения.
- Строго сопоставляй ключи с products.json и categories.json. Не генерируй ссылки на несуществующие файлы. Промпт не является готовым изображением.

## 12. Правовые и операционные вопросы — launch-content-checklist.md

Только checklist для владельца/разработчика и профильного специалиста: Impressum, Datenschutz, AGB, Widerruf, цены/налоги, доставка, возвраты, права на logo/assets, обработка загруженных файлов, срок хранения, подтверждённые составы тканей и характеристики, доступность, услуги нанесения. Раздели демо и реальный торговый запуск.

Для каждой позиции: какие факты нужны, кто подтверждает, где они отображаются. Не обещай правовую готовность сайта.

## 13. Контроль согласованности — content-validation.md

Проверь и отчитайся: 25 продуктов, 5 категорий, 150 уникальных SKU, корректные связи, целые неотрицательные остатки, положительные цены, одинаковые цвета, существующие size guides/image keys, одинаковые условия во всех текстах, отсутствие выдуманных business facts.

Если нельзя реально выполнить программную проверку — напиши «ручная проверка», не заявляй запуск валидатора. Перечисли вопросы и недостающие данные отдельно.
