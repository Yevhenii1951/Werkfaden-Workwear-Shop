# WW-022: The quote says discount, not agreed price

Status: in progress (branch `fix/ww-022-quote-discount-wording`).

Surface: `S` (storefront copy only).

## Intent / delivers

Closes the quote-wording finding of the 2026-10-25 review.

A quote is realised as a fixed, single-use order discount for one week in the
region — not as an order priced from the quote. The storefront said otherwise:
the intro promised "einen unverbindlichen Preis", the detail page labelled the
amount "Angebot:", and the success card called it "Ihr persönlicher
Rabattcode". A shopper could reasonably expect the offered total to be the
price of the requested items; holding the code, they could take the full
discount off any cart in the shop instead.

The mechanism stays (user decision, 2026-10-25: an honest coupon beats a
draft-order rewrite). The copy now says what the code is:

- `/angebote` intro: an offer leads to a one-off discount code over the offered
  amount for one order in this shop.
- `/angebote/[id]`: "Angebotener Rabattwert:" plus a sentence naming the seven
  days and the fact that the code is a fixed order discount, not bound to the
  requested items — marked as a demo limitation.
- Accept result: "Ihre Anfrage ist angenommen" instead of "Ihr Angebot ist
  angenommen", with the same demo sentence.

Nothing. WW-013 built the quote pages; WW-016 built the code.

## Context to read

This ticket + ../contract.md (quote lifecycle) + `src/api/store/quotes/[id]/accept`

## Verification scenario

GIVEN a quoted request WHEN the buyer opens `/angebote/<id>` THEN the page
presents the offered amount as a discount value, states its validity and that
it is not tied to the requested items; and GIVEN the buyer accepts THEN the
result names it a discount code with the same limitation.

## Acceptance criteria

- No storefront copy on `/angebote`, `/angebote/[id]` or the accept result
  presents the offered total as the price of the requested items.
- The seven-day validity and the single-use character are stated where the code
  appears.
- The demo limitation ("fester Bestellrabatt, nicht an die angefragten Artikel
  gebunden") is visible on the detail page and in the accept result.
- `npm run check:ui`, `npm run build:ui` and a browser pass over the three
  states (quoted, accepted, history list) stay green.

## Non-goals

No change to the discount mechanism, the promotion rules, the price shown at
checkout, or the backend. No draft-order flow. No legal rewording of AGB or
Widerruf.

## Known limits

- The demo limitation is written into the page rather than into a policy page,
  because the shop is a demo and has no operator to publish one.
- The code can still be applied to a cheaper cart than the quote assumed; the
  copy states it, and closing that gap needs the draft-order mechanism this
  ticket explicitly does not build.
