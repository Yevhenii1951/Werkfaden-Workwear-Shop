# WW-011: Product search coverage and open-item closure

Status: complete (2026-10-18).

## Intent / delivers

Closes the long-standing "`/store` InstantSearch 404" open item with evidence.
Live verification (2026-10-18) shows search already works end-to-end: the
Search Module is part of Medusa 2.21.2 default modules (postgres provider),
`src/search/product.ts` defines the product index, `configureStoreSearch`
exposes it on `POST /store/search`, the seed ingests documents, and the
storefront InstantSearch page filters/facets/typo-tolerance correctly. What is
missing is regression coverage and honest docs.

## Blocked by

Nothing.

## Complexity

Implementation: low (tests + docs). Review: medium (documents a security-
adjacent public endpoint). Fresh read-only review not required by scope, but
the PR description carries the live evidence.

## Context to read

This ticket + ../contract.md + ../state.md.

## Verification scenario

GIVEN an ingested product in the isolated test database WHEN an anonymous
request with a publishable key searches the product index THEN hits contain
the product; WHEN the index is unknown or the key is missing THEN the request
is rejected without leaking index internals.

## Acceptance criteria

- Integration spec `ww-011-search.spec.ts` on the throwaway test DB: happy
  path search returns the ingested product as a hit; unknown index → 404-shaped
  rejection; missing publishable key → 400; malformed body → 400. Search is
  never allowed to read outside the exposed index.
- `npm run check` green; integration count grows by the new spec.
- `state.md` / `handover.md` drop the stale InstantSearch-404 open item and
  state the verified behaviour instead.
- No production-code change expected; any code change discovered during the
  ticket is reported, not silently widened.

## Resolution

The Medusa integration runner snapshots the test database before the first
test and terminates its active connections. Search startup seeding can still be
running at that point, so the snapshot interrupted its transaction. The suite
now waits for the product index to become ready in its `beforeAll`, before the
runner takes that initial snapshot. No production code changed.

Verification: isolated WW-011 spec passes (5/5); `npm run check` passes with
backend unit 39/39, storefront unit 24/24, and integration HTTP 20/20.

## Non-goals

No new search UI, no new index fields, no search-module swap, no
relevance tuning beyond what the index already declares.

## Checks / browser evidence

- Live browser evidence already captured 2026-10-18: `/de/store?q=shirt`
  renders hits; free-text "Hose" narrows to "Arbeitshose Stretch"; facet
  counts render; all `POST /store/search` calls return 200. Re-verify after
  the test lands if the dev server is running.
